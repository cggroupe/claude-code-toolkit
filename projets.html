Créer un projet

La méthode pour démarrer un projet propre, structuré, qui restera maintenable dans 6 mois.

Le checklist du nouveau projet

  1. Créer un dossier dédié

    Toujours un dossier par projet. Pas de tout-en-un. Sur le Bureau ou dans ~/Documents/projets/.

    Création du dossier
    mkdir mon-nouveau-projet && cd mon-nouveau-projet

  2. Ouvrir le dossier dans VS Code

    File → Open Folder → sélectionner votre dossier. VS Code = 1 fenêtre = 1 projet.

  3. Lancer /init

    Claude scanne le projet (vide ou existant) et propose une première structure + CLAUDE.md.

    Init
    /init

  4. Compléter CLAUDE.md

    Le fichier CLAUDE.md est la bible du projet. Y mettre :

    • Objectif business : que fait ce projet ? Pour qui ?
    • Stack technique : langages, frameworks, services externes
    • Conventions : style code, langue (français/anglais), nommage
    • Règles métier : tout ce qui n'est pas dans le code mais qu'il faut respecter (RGPD, TVA, processus interne)
    • Interdits : ce que Claude ne doit jamais faire (push --force, supprimer X, modifier Y)

  5. Activer le pattern Karpathy

    Création de wiki/, sources/, log.md, MAP.md. Voir page dédiée.

    Bootstrap Karpathy
    Initialise le pattern Karpathy : crée wiki/, sources/, log.md, MAP.md. Scanne le projet existant et génère les premières notes wiki. Format markdown, français, frontmatter YAML.

  6. Configurer les MCP du projet

    Quels outils externes ce projet va utiliser ? (Apify pour prospection, fal.ai pour vidéo, Stitch pour design…) Installer dans Claude Code.

    Voir page MCP.

  7. Versionner avec git

    Sauf raison contraire, toujours versionner avec git. Même pour les petits projets marketing.

    Setup git + GitHub
    git init && git add . && git commit -m "Init projet" && gh repo create mon-nouveau-projet --private --source=. --push

  8. Premier vrai prompt

    Demander à Claude une grande tâche en plan mode. Lire le plan, ajuster, exécuter.

    Premier vrai prompt en plan mode
    Passe en plan mode. Voici ma mission : [DÉCRIRE PROJET]. Propose-moi un plan d'attaque en 5-10 étapes, avec : - Les fichiers à créer - Les dépendances à installer - Les MCP à utiliser - Les risques / décisions à prendre Ne code rien tant que je n'ai pas validé.

Les règles d'or

1. Un dossier = un projet. Ne mélangez jamais 2 sujets dans le même dossier VS Code, Claude se perd.

2. CLAUDE.md à jour = projet propre. Quand vous prenez une décision importante, ajoutez-la dans CLAUDE.md. C'est ce que Claude relit en premier.

3. Pas de secrets en clair. Toutes les clés API dans .env (jamais commit) ou en variables d'environnement. Ajoutez .env dans .gitignore immédiatement.

4. Plan mode pour les grosses décisions. Refonte, gros refactor, mise en prod : toujours en plan mode. On lit, on valide, on exécute.

5. Log + wiki avant fin de session. Avant de fermer VS Code : "mets à jour le wiki et log.md avec ce qu'on a fait aujourd'hui". Sinon vous perdez le contexte.
