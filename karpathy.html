Pattern Karpathy 🧠

L'astuce qui transforme Claude en collègue qui se souvient de tout. Sans ça, il oublie et casse votre projet.

En 1 phrase. Vous demandez à Claude de tenir un cahier de notes sur votre projet (1 page par feature, par bouton, par règle). Avant chaque modif, il relit son cahier. Avant chaque fin de séance, il met le cahier à jour. Le projet ne casse plus.

Avant / Après
SANS pattern Karpathy
  • Vous : « Modifie la page tarifs »
  • Claude : casse le bouton "Réserver" (il a oublié à quoi il servait)
  • Vous : « Refactor le formulaire »
  • Claude : duplique la logique (il ne savait pas qu'elle existait déjà)
  • 3 mois plus tard : Claude n'a aucun contexte, vous réexpliquez tout
AVEC pattern Karpathy
  • Vous : « Modifie la page tarifs »
  • Claude : relit la note "bouton-reserver" avant de toucher
  • Vous : « Refactor le formulaire »
  • Claude : réutilise la logique existante documentée dans le wiki
  • 3 mois plus tard : Claude relit le wiki en 30s et est opérationnel

Une note wiki, c'est quoi ?

Chaque note dans wiki/ suit ce format simple : en-tête YAML + corps markdown avec liens vers d'autres notes en [[double crochets]].

wiki/composants/bouton-reserver.md
---
name: bouton-reserver
type: composant
description: CTA principal de la page tarifs
last-updated: 2026-05-22
---

# Bouton "Réserver"

Composant React situé sur [[tarifs]].
Déclenche le formulaire [[formulaire-devis]].

## Comportement
- Couleur orange CG : #f97316
- Au clic : analytics.track('cta_clicked') puis modal
- Désactivé si l'utilisateur n'est pas connecté

## Dépendances

- Tracking depuis [[lib-analytics]]

Voir [[log]] entrées 2026-05-15, 2026-05-22.

L'idée des [[wikilinks]] : chaque note pointe vers les autres. Claude peut "suivre les liens" comme sur Wikipedia. Le contexte n'est jamais perdu.

Karpathy vs RAG

Le RAG (recherche sémantique sur chunks) est complémentaire, pas concurrent.

RAG

Pour les gros corpus externes

  • 500 PDFs normes DTU
  • 10 000 articles juridiques
  • Transcripts interviews
  • Bases connaissances volumineuses
Recherche par similarity. Bon en volume, moins précis sur contexte.
KARPATHY

Pour le contexte projet

  • Code, pages, composants
  • Règles business spécifiques
  • Décisions équipe / historique
  • Connaissance interne projet
Lecture directe + wikilinks. Excellent en précision, maintient le contexte.

💎 Le combo gagnant = la "bombe atomique". Wiki Karpathy pour comprendre le projet en 30s + RAG pour fouiller un corpus volumineux quand besoin. Vitesse + précision + contexte.

Cas concrets AUTAF

🏗️ Site AUTAF (refonte)

Wiki = 1 note par page (accueil, services, contact) + 1 note par composant (bouton CTA, formulaire). Quand vous demandez "ajoute des témoignages", Claude relit le style maison et produit cohérent.

🎯 Base prospects

Wiki = 1 note par gros prospect (historique, décideur, sensibilité prix). Sources = exports Apify, transcripts d'appels. Reprise 3 mois plus tard = 5 lignes de récap.

📹 Personal brand TikTok

Wiki = 1 note par pilier de contenu, par format gagnant, par audience. "Fais-moi un calendrier 30j" → Claude reproduit ce qui a déjà marché.

⚖️ Veille normes BTP

Combo : RAG sur 500 PDFs DTU + wiki Karpathy qui synthétise. "Conforme DTU 25.41 ?" → réponse en 10s via wiki, RAG si besoin précision.

Bootstrap en 1 prompt
Activer Karpathy sur n'importe quel projet
Initialise le pattern Karpathy sur ce projet : 1. Crée wiki/ avec sous-dossiers : pages/, composants/, business-logic/, decisions/ 2. Crée MAP.md (index) et log.md (journal append-only) à la racine 3. Crée CLAUDE.md avec : règles, glossaire, classification notes 4. Scanne le projet existant et génère 1 note par feature 5. Chaque note : frontmatter YAML + corps markdown + [[wikilinks]] 6. Ajoute 1ère entrée dans log.md résumant le bootstrap Format français, max 100 lignes par note.
Les 5 règles d'or
1

Le wiki = vérité du contexte

Pas du comportement. Si code et wiki divergent, faites confiance au code et corrigez le wiki.

2

Modif code = update wiki

Toujours les deux ensemble. Sinon le wiki devient inutile en quelques semaines.

3

log.md = append-only

On n'efface jamais. 1 entrée par changement significatif. Votre journal de bord.

4

Lint hebdo obligatoire

Une note jamais liée = orphelin = bruit. Claude doit nettoyer ou rattacher.

5

CLAUDE.md = la bible

Vous l'éditez à la main, Claude le relit en premier à chaque session.

⚡ Le résultat

Vos projets restent maintenables 6 mois plus tard. Claude ne casse plus ce qu'il ne comprend pas.
