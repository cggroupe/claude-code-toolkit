Bonnes pratiques 📖

Les règles simples qui évitent les boulettes coûteuses. À lire avant la 1ère session.

🎯 L'esprit du guide. Pas de jargon. Pas de leçon de morale. Juste les réflexes qui font la différence entre un usage pro et un usage qui vous fait perdre temps + argent + crédibilité.

Les 10 règles d'or
1️⃣

Toujours commencer en plan mode

Avant une grosse tâche, demandez à Claude de réfléchir d'abord. Tapez /plan ou Shift+Tab. Il propose, vous validez, puis il exécute.

Pourquoi. Évite les heures perdues sur une mauvaise piste.
2️⃣

Lire avant de cliquer "Allow All"

Claude demande l'autorisation pour chaque action sensible. Lisez ce qu'il propose avant de cliquer. Surtout les commandes rm, delete, git push --force.

Pourquoi. 1 clic sans lire peut effacer des heures de travail.
3️⃣

/clear quand ça part en vrille

Si Claude boucle sur une mauvaise piste, ne pas insister. Tapez /clear pour repartir d'une feuille blanche, puis reformulez votre demande différemment.

Pourquoi. Plus on insiste sur une erreur, plus on s'enlise.
4️⃣

1 dossier = 1 projet

Ne mélangez jamais deux sujets dans le même dossier VS Code. Toujours créer un dossier dédié par projet (sur le Bureau, par exemple).

Pourquoi. Claude se perd dans l'arborescence sinon.
5️⃣

Toujours dire le budget max

Avant tout job utilisant fal.ai / PiAPI / Apify (services payants), précisez : « Budget max : $X. Si tu dépasses, STOP. »

Pourquoi. 6 essais Veo3 ratés = $36 brûlés sans résultat.
6️⃣

Vérifier les chiffres IA

Les IA hallucinent. Surtout sur les chiffres, dates, noms propres, normes. Toujours vérifier ce qui touche au légal, médical, BTP/normes.

Pourquoi. Crédibilité métier = irrécupérable si on cite un faux DTU.
7️⃣

Sauvegarder en mémoire

Quand vous découvrez une préférence/règle qui doit tenir entre sessions, dites « Remember : [...]». Claude l'écrit dans sa mémoire long-terme.

Pourquoi. Moins de répétition = plus de vrai travail.
8️⃣

Git commit toutes les 30 min

Sur projets versionnés : commit régulier. Si Claude casse quelque chose, vous revenez en arrière sans drame.

Pourquoi. Sauvetage en 1 commande au lieu d'1 heure de rage.
9️⃣

Pas de secrets en clair

Jamais de clé API, mot de passe, token, dans un fichier commit. Toujours dans .env + .env dans .gitignore.

Pourquoi. Une clé leakée = abus de votre compte ($$$$).
🔟

Tester avant publier

Vidéo, landing, email cold : jamais push direct en prod. Test sur soi/un collègue, puis publication.

Pourquoi. Erreur publique = capture d'écran qui circule.
Les pièges à éviter
❌ À NE PAS FAIRE
  • Lancer Claude Code dans ~/Desktop directement
  • Cliquer "Allow All" sans lire la commande proposée
  • Coller du code IA en prod sans relire
  • Publier les chiffres d'une IA sans vérifier
  • Mettre les API keys dans le code source
  • Donner des données clients réelles en test
  • Demander 50 vidéos Veo3 sans budget cap
  • Croire que Claude se souvient de la dernière session
✓ À FAIRE
  • Créer un dossier dédié par projet
  • Plan mode avant les grosses tâches
  • Relire le code généré, tester en local
  • WebSearch + sources pro pour les chiffres
  • Variables d'env .env + .gitignore
  • Données test bidon pour les essais
  • Budget cap explicite dans le prompt
  • Pattern Karpathy = wiki à jour avant clôture session
IA en général — ce qu'il faut savoir

🧠 L'IA hallucine

Claude/ChatGPT peuvent inventer des choses avec aplomb : statistiques fausses, URLs inexistantes, citations imaginées, articles de loi qui n'existent pas.

Réflexe : tout ce qui touche au légal, médical, normes BTP, dates précises → WebSearch + source officielle.

📅 Knowledge cutoff

Les IA ont une "date de coupure" de connaissances. Claude 4.7 sait jusqu'à janvier 2026. Au-delà : il ne sait pas (ou pire, il invente).

Réflexe : pour l'actualité récente, lui demander de faire un WebSearch explicite.

🔒 RGPD & données clients

Vos prompts peuvent être stockés/analysés par le fournisseur (Anthropic, OpenAI). Ne collez jamais : RIB, mot de passe, dossier médical, NIR, données clients réelles.

Réflexe : anonymiser avant collage. "Client X" au lieu de "Marie Dupont".

💰 Le vrai coût

L'IA semble gratuite mais : abonnement Claude (20-200$), MCP payants (fal.ai $6/clip, Apify, DataForSEO), temps humain de relecture.

Réflexe : faire un budget mensuel total. Tracker dépenses fal/Apify par dashboard.

👤 Pas un remplacement de l'expertise

L'IA accélère 10× ce que vous savez faire. Elle ne remplace pas le jugement métier. Sur le BTP, l'assurance, le juridique : relecture humaine obligatoire.

Réflexe : "trust but verify".

🎭 Le syndrome du faux pro

L'IA répond avec un ton très assuré, même quand elle a tort. Ce n'est pas parce que ça semble juste que c'est juste.

Réflexe : demander à Claude lui-même "es-tu sûr ? vérifie tes sources".

Workflow type d'une journée propre

  1. Matin — ouvrir un projet existant

    VS Code → ouvre le dossier projet → ouvre Claude Code → tapez /resume pour reprendre la conversation. Premier prompt : "Lis CLAUDE.md, MAP.md et log.md, fais-moi un résumé d'où on en est".

  2. Définir la mission du jour

    "Aujourd'hui je veux faire X. Voici les contraintes : Y. Budget max : $Z. Passe en plan mode et propose-moi un plan d'attaque."

  3. Travailler par cycles courts

    Petite tâche → tester → commit. Petite tâche → tester → commit. Plutôt que 4h de génération massive et "espérer que ça marche".

  4. Si bloqué > 15 min : reset

    Tapez /clear, reformulez le problème en partant du résultat attendu (pas du code intermédiaire). Souvent ça débloque.

  5. Avant fin de session : update wiki + log

    "Met à jour le wiki/ et log.md avec ce qu'on a fait aujourd'hui. Format synthétique, dates, décisions clés." Pattern Karpathy obligatoire.

  6. Commit final + push

    git add . && git commit -m "..." && git push. Demain vous reprenez exactement où vous avez laissé.
