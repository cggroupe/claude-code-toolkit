10 règles d'or 📖

Les réflexes qui font la différence entre un pro et quelqu'un qui brûle son crédit.

Lire 5 minutes maintenant = économiser 5 heures plus tard.
Les règles
1

📋 Plan mode avant grosse tâche

Tapez /plan ou Shift+Tab. Claude propose, vous validez, puis il exécute.

Pourquoi Évite 2h gaspillées sur une mauvaise piste.
2

👀 Lire avant "Allow All"

Lisez la commande proposée. Surtout rm, delete, git push --force.

Pourquoi 1 clic aveugle = des heures de travail effacées.
3

🧹 /clear quand ça boucle

Si Claude part en vrille, n'insistez pas. Tapez /clear, reformulez.

Pourquoi Plus on insiste sur une erreur, plus on s'enlise.
4

📂 1 dossier = 1 projet

Toujours un dossier dédié. Pas de "tests-claude" tout-en-un.

Pourquoi Claude se perd dans une arborescence mixte.
5

💸 Toujours dire le budget max

« Budget max : $X. Si tu dépasses, STOP. » en début de prompt.

Pourquoi 6 essais Veo3 ratés = $36 brûlés sans résultat.
6

✅ Vérifier les chiffres IA

L'IA hallucine. Toujours WebSearch sources officielles pour normes/lois/chiffres.

Pourquoi Citer un faux DTU = crédibilité métier ruinée.
7

🧠 Sauvegarder en mémoire

« Remember : [...]» pour les règles qui doivent tenir entre sessions.

Pourquoi Moins de répétition = plus de vrai travail.
8

💾 Git commit toutes les 30 min

Commit régulier sur tout projet versionné.

Pourquoi Si ça casse, rollback en 1 commande.
9

🔒 Jamais de secrets en clair

Clés API toujours dans .env + .env dans .gitignore.

Pourquoi Une clé leakée = abus de votre compte ($$$).
10

🧪 Tester avant publier

Vidéo, landing, email : jamais push direct en prod. Test sur soi d'abord.

Pourquoi Erreur publique = capture d'écran qui circule.
À faire vs à éviter
❌ NE PAS FAIRE
  • Claude Code dans ~/Desktop direct
  • "Allow All" sans lire
  • Coller du code IA en prod sans relire
  • Publier des chiffres sans vérifier
  • API keys dans le code source
  • Données clients réelles en test
  • 50 vidéos Veo3 sans budget cap
✓ À FAIRE
  • Dossier dédié par projet
  • Plan mode avant grosses tâches
  • Relire + tester le code généré
  • WebSearch + sources pro
  • .env + .gitignore
  • Données bidon pour les essais
  • Budget cap explicite
L'IA en général
🧠

L'IA hallucine

Statistiques fausses, URLs inexistantes, articles de loi imaginés. Toujours vérifier le légal, médical, normes BTP.

📅

Knowledge cutoff janvier 2026

Claude 4.7 ne sait rien après cette date (sauf si WebSearch). Demandez explicitement à fouiller le web pour l'actu.

🔒

RGPD & données clients

Ne collez jamais RIB, mots de passe, données patients, NIR. Anonymisez avant. Vos prompts peuvent être analysés.

💰

Le vrai coût

Abonnement Claude (20-200$/mois) + MCP payants (fal $6/clip, Apify, etc.) + temps humain de relecture.

👤

Pas un remplacement de l'expertise

L'IA accélère 10× ce que vous savez faire. Ne remplace pas le jugement métier. Relecture humaine obligatoire sur BTP/assurance/juridique.

🎭

Le syndrome du faux pro

L'IA répond avec un ton assuré, même quand elle a tort. Trust but verify. Demandez à Claude lui-même de vérifier ses sources.

Workflow type d'une journée

VS Code → ouvre le dossier projet → ouvre Claude Code → /resume.

Prompt de reprise
Lis CLAUDE.md, MAP.md et log.md, fais-moi un résumé d'où on en est en 5 lignes.
Prompt de mission
Aujourd'hui je veux faire X. Contraintes : Y. Budget max : $Z. Passe en plan mode et propose-moi un plan d'attaque.

Petite tâche → tester → commit. Plutôt que 4h de génération massive + "espérer que ça marche".

Tapez /clear, reformulez en partant du résultat attendu (pas du code intermédiaire). Souvent ça débloque.

Prompt de clôture
Met à jour le wiki/ et log.md avec ce qu'on a fait aujourd'hui. Format synthétique, dates, décisions clés. Pattern Karpathy.
Commit final
git add . && git commit -m "session 22/05 - update wiki + features X Y" && git push
